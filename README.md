# VisaWorld

Двуязычный мобильный сайт визового агентства: русский `/`, казахский `/kk`, кабинет `/admin`.

## Что реализовано

- Адаптивная вёрстка, мобильное меню, выбор направления с переносом в форму, FAQ и диалог обработки данных.
- Серверное сохранение заявок в Cloudflare D1; записи не зависят от браузера посетителя.
- Администратор входит через ChatGPT; сервер сверяет email с секретной настройкой `ADMIN_EMAILS`.
- Поиск, статусы, заметки, CSV-экспорт последней 1 000 записей.
- Серверная валидация, согласие, honeypot, проверка Origin, ограничение повторов по телефону, idempotency key.
- Раздельные языковые адреса, metadata, canonical, hreflang, robots.txt, sitemap.xml.

## Разработка

Node.js 22.13+, npm, Git. В предоставленном checkout зависимости уже установлены. На новом компьютере: `npm ci`, затем `npm run dev`. Этот проект использует Vinext и Cloudflare Workers. Для локальной базы: `npm run build`, затем `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_spotty_nocturne.sql`. Не повторяйте уже применённую миграцию. Для изменения схемы создавайте новые миграции через `npm run db:generate`.

## Проверки

`node tests/server.test.mjs`

Серверные тесты изолируют базу и identity фикстурами; проверяют запрет доступа, валидацию, согласие, Origin, повторы, ограничение частоты, разрешённое чтение и обновление статуса. Сохранение реальной записи отдельно проверено в локальной D1 через браузер и SQL. Внешний запуск через другой хостинг требует отдельной настройки identity: доверять присланным клиентом oai-заголовкам на обычном публичном сервере нельзя.

## Публикация

Используйте существующий проект Sites из `.openai/hosting.json`; не создавайте новый проект для каждой правки. Сохраните и отправьте точное состояние исходников в подключённый репозиторий, соберите и опубликуйте версию. Не копируйте только index.html на статический хостинг: база и защищённый кабинет требуют Worker и авторизации Sites. Текущий режим — доступ только владельцу. Публичный режим включается отдельно перед запуском. Админка всё равно проверяет `ADMIN_EMAILS`.

Собственный домен подключается через Sites. Используйте только DNS-значения, выданные Sites. После смены домена обновите `metadataBase` в `app/layout.tsx` и опубликуйте версию. Карта сайта и robots.txt используют origin запроса.
